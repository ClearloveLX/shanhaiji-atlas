# 收录标准与文案规范 — 山海集 Atlas

> 三条线各管一件事：**硬性门槛**管「收不收」，**文案规范**管「怎么写」，
> **标签规则**管「怎么被找到」。三者都对着同一条 `entry`，写之前先读一遍。

---

## 一、硬性门槛（三条全过才收，缺一条直接不收）

| 门槛 | 怎么判定（动手做，不要凭印象） | 不过怎么办 |
|---|---|---|
| **1. 真实可访问** | 在**没有登录、没有代理**的干净浏览器里打开一次；`curl -sI <URL>` 看状态码不是 404/410/5xx，也不是跳到无关页面。链接必须是最终的正式地址，不是某个短链跳转的中间页 | 打不开就不收。**不要收「即将上线」的落地页** |
| **2. 核心功能可用** | 把它的主要功能真的用一遍：工具就做一次导出/生成，网站就看有没有内容，店铺就看能不能下单/到店。**首页好看但点进去什么都没有的，不算可用** | 功能不可用就不收（哪怕它很有名） |
| **3. 无恶意弹窗与强制下载** | 打开后等 10 秒：有没有弹广告窗、诱导下载客户端、假装成「你的电脑有风险」的假提示、自动跳转到应用商店；关掉弹窗后能不能正常用 | 有任意一条就不收，**并且不要再给它第二次机会**（这类站点会反复） |

补充两条边界：

- **`url` 只能填官方网站的第一入口**，不要填带一堆 UTM 参数的活动页。
- 收费不等于不收：**核心功能可长期免费用**的收（`price=freemium`），
  纯付费墙、连试用都不给的，按「核心功能不可用」处理。

## 二、加分项（决定它在列表里的排序与角标）

加分项不是"收不收"的条件，是**同样合格的两条之间先推荐谁**的依据。
每一条都对应一个 `attr` 标签，判断成立就打上：

| 加分项 | 打哪个标签 | 怎么确认 |
|---|---|---|
| **长期维护** | `attr/maintained` | 近 12 个月内有更新记录（更新日志、版本号、公告栏任一处能看出来） |
| **中文界面** | `attr/zh-ui` | 切到简体中文后**主要流程**都是中文；只有设置页中文不算 |
| **免登录可用** | `attr/no-login` | 无痕窗口打开就能完成主要操作，不用注册、不用短信验证码 |
| **无广告** | `attr/ads-free` | 没有弹窗、没有信息流广告、没有诱导下载按钮 |
| 完全免费 | `attr/free` | 核心功能长期免费，没有强制付费墙 |
| 免下载 | `attr/no-install` | 纯网页 / 小程序，不需要安装客户端 |
| 开源 | `attr/open-source` | 源码公开可查（能给出仓库地址就算） |

⚠️ `attr/need-proxy`（需境外访问）**不是加分项，是必须标明的事实**：
中国大陆直连打不开的，一定要打这个标签，否则访客点进去只会以为站坏了。

## 三、明确不收（四条，没有例外）

| 不收的类型 | 典型特征 | 怎么判定 |
|---|---|---|
| **需要安装来路不明客户端** | 想用核心功能先下载一个 `.exe` / `.apk` / 浏览器扩展，而且不说明是谁开发的、签名是否可信 | 看下载按钮指向的文件域名是不是官方域名；不是就判定为来路不明 |
| **频繁换域名** | 同一个东西一年换过两次以上域名（常见于被墙、被举报、跑路的站） | 搜一下它的历史域名，或看现有域名注册时间；**刚注册一个月的新域名不收** |
| **纯导流站** | 页面本身没有内容，唯一作用是把你导到公众号 / 微信群 / 私域客服 / 另一个 App | 通读首屏：如果拿掉所有"加微信""进群""下载 App"按钮后什么都不剩，就是纯导流 |
| **停止维护超过 2 年** | 最后更新在 2 年以上，且现在有明显坏掉的地方 | 找最近一次更新时间；功能还能正常用、只是没新功能的不算，**坏了又没人修**的才算 |

处理方式：

- 投稿来的 → 在 `/admin/submissions` 点「拒绝」，原因选 **不符合收录标准** 或 **链接失效**（按实际情况）。
- 已经收录、后来变成上面四种的 → 把 `status` 改成 `dead`（人工确认），
  并在 `note` 里补一句为什么下架，别直接删（删除是软删除，进 `/admin/trash`）。

## 四、标签怎么打

### 4.1 基数上限（硬规则，后台和 Zod 双重拦截）

| 维度 | `dim` | 一条最多几个 | 必填 |
|---|---|---|---|
| 主题 | `topic` | 3 | 否 |
| 场景 | `scene` | **3** | **至少 1 个** |
| 属性 | `attr` | 4 | 否 |
| 平台 | `platform` | **6** | 否 |
| 价格 | `price` | 1 | 否 |
| 质量 | `quality` | 2 | 否 |

`platform` 的 6 是**枚举项**不是倾向：`web` / `ios` / `android` / `windows` / `macos` / `miniprogram`
一共就 6 个，有官方客户端就勾上。「按平台筛选」漏掉一个真有的客户端，比多打两个更糟 ——
所以真正要克制的是 `scene` 和 `attr`（见 [`TAGS.md`](TAGS.md) 第 1 节）。

### 4.2 总数 3-8 个

**一条条目的标签总数控制在 3-8 个。** 少于 3 个说明定位没想清楚（连场景都没打全），
超过 8 个说明这条什么都想沾 —— 标签页里它会在十几个地方冒出来，把真正对口的条目挤下去。

数的时候**把 `type` 也算进去**：`type` 是必有的一个，不用在 `entry_tags` 里重复打标签。

### 4.3 `scene` 最多 3 个，而且必须是「同一时刻会同时成立」的

判断该打哪个 `scene`，只问三个问题，按顺序问：

1. **用户在什么状态下会打开它？**
   ——「上班摸鱼时打开」是 `fun`，「上班干活时打开」是 `work`，两个都占才打两个。
2. **它的主要用途属于哪个场景？只选最主要的 1 个。**
   —— 一个记账工具，主要用途是记账 → `money`；「顺手也能算汇率」不构成 `travel`。
3. **第三个场景是真的跨界，还是硬凑？**
   —— 只有「用户会在完全不同的两种状态下用它」才打第三个。
   比如小红书：`fun`（刷内容）+ `travel`（查攻略）+ `food`（找店），三个都成立；
   而一个 PDF 工具打 `work,study,create` 就是硬凑，它其实就是 `work`。

`scene` 打超过 3 个等于没打 —— 首页「按场景逛」的字号是按计数排的，
什么都沾的条目会把每个场景的分母都撑大。

### 4.4 常见打错的样子

| 打错了 | 为什么错 | 应该怎么打 |
|---|---|---|
| 把「免登录」打成 `scene` | 它是**属性**，不是使用场景 | `attr/no-login` |
| 给纯英文界面打 `attr/zh-ui` | 标签与事实不符，比不标更伤 | 不打；或者等它出中文再补 |
| 给线下咖啡店打 `platform/ios,android` | 平台维度说的是**软件形态**，线下店用不上 | 不打 `platform` |
| 一条打 5 个 `scene` | 超过上限 3，且等于没打 | 删到最多 3 个，只留最主要的 |
| 造同义标签（「免登录」+「无需注册」） | 筛选栏出现两个一样的东西 | 用 `/admin/tags` 的**合并**功能收拢成一个 |
| 把私人想法打成公开标签 | 「想去的店」这类只能放在 `private` 维度 | 见 [`PRIVACY.md`](PRIVACY.md) 的私密标签 |

## 五、`featured` 与 `editor-pick` 的判定，以及 15% 红线

这两个东西不是一回事，别混：

| | `entries.featured` | `quality/editor-pick` 标签 |
|---|---|---|
| 是什么 | 条目表上的一个布尔列 | 质量维度的一个标签 |
| 前台表现 | 进首页「编辑精选」横滑条 | 详情页/卡片上的「编辑精选」角标，标签页里可筛 |
| 数量 | **首页最多显示 6 条** | 全站占比 **不超过 15%** |
| 怎么改 | `/admin/entries` 列表里直接切 | 编辑条目时挂/摘 `quality/editor-pick` 标签 |

### 5.1 `editor-pick` 的判定标准（四条全中才给）

1. **自己真的在长期用**，不是「看起来不错」；
2. **至少用过 3 个月**，不是这周才收录的新东西（新东西用 `quality/new`，那个要**人工挂**）；
3. **在同类里是首选**：同一个用途收录了 5 个，只有一个能挂这个标签；
4. **不会因为换域名、涨价、关停就立刻下架** —— 判断依据是它有稳定的维护记录。

### 5.2 `featured` 的判定标准（在 `editor-pick` 之外再挑）

首页那 6 个位置是**全站最贵的展示位**，标准是「新访客第一次来，用它来判断这个站值不值得收藏」：

- 打开就能用，不需要注册、不需要装东西（`attr/no-login` + `attr/no-install` 至少占一个）；
- 一句话能说清它是干什么的（`summary` 写得出来，不是"功能强大"）；
- 至少覆盖两种不同类型的用户（6 条不要全是设计工具或全是吃喝）。

### 5.3 15% 红线怎么算

```bash
# 服务器上跑（只有公开条目计入分母：私密/不列出条目不该拉低比例）
sqlite3 /opt/atlas/data/atlas.db "
select
  (select count(*) from entry_tags et
     join tags t on t.id = et.tag_id
     join entries e on e.id = et.entry_id
    where t.dim = 'quality' and t.slug = 'editor-pick'
      and e.deleted_at is null
      and e.visibility = 'public') * 100.0
  / (select count(*) from entries
      where deleted_at is null and visibility = 'public') as editor_pick_pct,
  (select count(*) from entries
    where featured = 1 and deleted_at is null and visibility = 'public') as featured_count;"
```

红线：

- `editor_pick_pct` **不得超过 15**（公开条目数变多时分母变大，比例会自然下降，
  但**不许为了凑比例去批量打标签**）；
- `featured_count` **不得超过 6**（首页只显示 6 条，多了就是白占位）。

### 5.4 超了怎么办

**先摘，不加。** 从最旧的、最少用的开始往下摘，摘到比例回到 15% 以内。
`editor-pick` 是"我确实长期在用"的证明，不是用来提升某条排名的工具 ——
满屏都是「精选」，等于没有精选。

## 六、文案规范

### 6.1 `name` / `nameEn` / `slug`

| 字段 | 规则 | 例 |
|---|---|---|
| `name` | 官方名称原样写，不要翻译、不要加形容词；线下店用「品牌名（门店区域）」，但**一个品牌只建一条**，门店进 `entry_branches` | `Figma`、`山海咖啡（静安寺店）` |
| `nameEn` | 只有官方英文名和中文名不同时才填 | `Figma` |
| `slug` | 全小写 kebab-case，**和 URL 一致，定下就不要改**（改了就断链） | `figma`、`shanhai-coffee` |

### 6.2 `summary`：写「这是什么 + 适合谁」

一句话（30-80 字，上限 200）里必须同时包含两件事：

1. **这是什么**：哪一类东西、能干什么（具体到功能，不是"很强大"）；
2. **适合谁**：什么情况下的人该用它（学生 / 开发 / 开店 / 带娃 / 一个人住…）。

```
✅ 在线界面设计工具，多人可以同时改同一份设计稿，适合做原型、UI 稿和简单插画；个人免费版够用。
✅ 一个网页端的小工具集合，包含 JSON 格式化、时间戳转换、Base64 编解码；适合开发时随手查一下，不用装客户端。
❌ 全网最强！功能强大，不容错过，赶紧收藏！
```

写法上的四条禁忌：不写广告词（最强/最好用/必备）、不写「本站/我们/我推荐的」、
不用感叹号、不写没有信息量的开场（「这是一款…」）。

### 6.3 `note`：写「我为什么收录它」

`note` 是**给自己和访客看的第一人称判断**，长度不限，一段话就够。写三件事：

1. **我实际怎么用它**（具体到某个场景、某个功能）；
2. **它好在哪一点**（和同类比，一句话说得出差别）；
3. **有什么坑或前提**（要收费、要代理、周末人多、只支持 Windows…）。

```
✅ 设计稿和原型能放在一个文件里，改完直接发链接让同事在上面评论，省掉导出和来回传文件。
   免费版对个人足够，多人协作才需要付费。
❌ 很好用，推荐。
❌ （把 summary 复制一遍）
```

⚠️ `note` 里**不要写私人信息**（老板微信、实际花费、私人评价）。
那些属于 `entry_private` 表，只有 `/admin` 和 `/me` 看得到，写在 `note` 里等于公开。

### 6.4 标签的 `desc`：30-60 字

`desc` 渲染在标签聚合页顶部，**这是那个页面的 SEO 正文**，不是装饰。写清：
这个标签收什么、不收什么。

```
✅ 办公：文档协作、流程管理、会议记录、表单收集这类提高干活效率的东西。
   不收录单纯的网盘和聊天工具。
```

### 6.5 全站统一的文案禁忌

- 面向访客的文案**不出现「本站」「我们」这类自称**，直接说事实。
- 不用 emoji 当图标或装饰（图标一律 lucide-react）。
- 数字用阿拉伯数字（`30 天`、`5 分钟`），不要「三十天」。
- 专有名词保留官方大小写（`GitHub` 不是 `Github`，`iOS` 不是 `ios`）。

## 七、四个正例

### 正例 1 · 外部工具（`type=tool` + `link_mode=external`）

```
name      Figma
slug      figma
summary   在线界面设计工具，多人可以同时改同一份设计稿，适合做原型、UI 稿和简单插画；个人免费版够用。
note      设计稿和原型能放在一个文件里，改完直接发链接让同事在上面评论，省掉导出和来回传文件。
          免费版对个人足够，多人协作才需要付费。收录是因为它在浏览器里就能跑，不用装客户端。
url       https://www.figma.com/       ← 前台只通过 /go/figma 跳出去
tags      type=tool · scene=create,work · platform=web,macos · price=freemium · attr=maintained
          （共 6 个，scene 2 个）
```

### 正例 2 · 线下好店（`type=shop` + `link_mode=place`）

```
name      山海咖啡（静安寺店）
slug      shanhai-coffee
summary   以手冲为主的社区咖啡店，人均 30-40 元，适合一个人坐着看书或者临时办公；
          静安寺地铁站 2 号口步行 5 分钟。
note      工作日下午三点后基本有位子，靠墙那排有插座。老板会按口味推荐豆子，不催单，
          所以也打了「办公」场景。周末下午人多，不建议带电脑去抢座位。
tags      type=shop · scene=food,work · price=freemium          （共 3 个，scene 2 个）
branches  上海 · 静安区 · 某某路 12 号 1 楼（经纬度已在地图上人工确认过那个点）
qrcodes   店主微信（长期有效）
```

> **门店地址是可选的**（字段定义见 [`DATA-MODEL.md` 2.1](DATA-MODEL.md)）。三种填法：
>
> | 什么店 | 怎么填 | 详情页给访客什么 |
> |---|---|---|
> | 独立小店、常去的那几家 | `link_mode=place` + 1-3 条 `entry_branches` | 逐个门店的地址 + 高德/百度/Apple 导航按钮 + 位置示意图 |
> | 连锁品牌（迪卡侬、盒马、MUJI 这种几百家的） | `link_mode=place`，门店列表**留空**，只填 `mapQuery` | 「在地图上找最近的」按钮组，访客在地图 App 里按自己的位置找最近一家 |
> | 线上店，但线下也有实体店 | `link_mode=external` + `mapQuery` | 主按钮仍是「访问官网」，侧栏另外给「在地图上找最近的」 |
>
> `mapQuery` 填「地图 App 里能搜到的名字」：条目名带英文时必须单独填
> （「小佩 PETKIT」→ `小佩`、「盒马 Freshippo」→ `盒马鲜生`、「宜家 IKEA」→ `宜家`）；
> 留空则直接用条目名（「海底捞火锅」「单向空间」这种本来就搜得到）。
>
> **不要为了看起来完整去补几十条门店地址** —— 会过期、会漏、每次都要改。
> 地图 App 里的 POI 数据永远比我们新，把「按距离找最近」这件事交给它更准。

### 正例 3 · 自研工具（`type=tool` + `link_mode=internal`）
```
name      二维码生成器
slug      qr-generator
summary   在浏览器里生成二维码，可以调尺寸和容错等级，图片不出浏览器；
          适合给店铺、名片、海报做二维码。
note      自己写的。起因是群里发的群码 7 天就失效，需要一个随时能重出、内容自己说了算的工具。
          纯前端，不上传服务器，所以也标了免登录。
component qr-generator        ← 必须和 src/tools/registry.ts 里的 key 完全一致
tags      type=tool · scene=create,work · platform=web · attr=free,no-login,no-install · price=free
          （共 7 个，scene 2 个）
```

### 正例 4 · 源码分享（`type=code` + `link_mode=external`）

```
name      shadcn/ui
slug      shadcn-ui
summary   能直接拷进项目的 React 组件源码，不是装一个包就完事，改样式不用跟库的作者较劲；
          适合想自己掌控 UI 层的中小项目。
note      Tailwind 项目里最省事的起点：想要哪个组件就拷哪个，代码在仓库里，升级不会把改动冲掉。
          收录是因为它的源码本身就是文档，读一遍就知道该抄哪段。
url       https://ui.shadcn.com/       ← 前台只通过 /go/shadcn-ui 跳出去
tags      type=code · scene=create,work · platform=web · price=free · attr=maintained
          （共 6 个，scene 2 个）
```

> **源码分享和工具分享怎么分**：能用起来、要用它解决问题的进工具；主要是**读和抄代码**的
> （组件库、模板、脚手架、示例工程）进源码分享。仓库里同时挂着在线 Demo 的，看你想让访客先做什么。
> 两种情况都是 `link_mode=external`，前台都走 `/go/{slug}`，只是进 `/tools` 还是 `/codes` 的区别。

四条正例的共同点：`summary` 都能一句话说清「是什么 + 适合谁」；
`note` 都能看出**自己真的用过**；标签都在 3-8 个、`scene` 都在 3 个以内；
没有一条打了 `editor-pick` —— 那是要攒够 3 个月才给的东西。

## 八、三个反例

### 反例 1 · `summary` 写成广告词，信息量为零

```
❌ name      某某全能工具箱
   summary   全网最强！功能强大，不容错过，赶紧收藏！
```

问题：没有「这是什么」（哪一类、能干什么），也没有「适合谁」；
感叹号和"最强"这类词半年后自己看着都尴尬；访客要靠点进去才知道是什么。

```
✅ summary   一个网页端的小工具集合，包含 JSON 格式化、时间戳转换、Base64 编解码；
             适合开发时随手查一下，不用装客户端。
```

### 反例 2 · `note` 抄 `summary`，或者只有结论没有依据

```
❌ note   很好用，推荐。
❌ note   在线界面设计工具，多人可以同时改同一份设计稿……（把 summary 复制了一遍）
```

问题：`note` 要回答的是「**我**为什么要收录它」。写「很好用」等于没写；
半年后回头看，你自己都不知道当时是看上它哪个功能，
下次同类站点出现时也没法判断该不该换掉它。

```
✅ note   自己用了两年，主要用来给店里的海报出二维码。它的容错等级能调到 H，
         印小了扫不出来时可以调高补救。缺点是导出只有 PNG，要做矢量图得换工具。
```

### 反例 3 · 标签堆砌，而且与事实不符

```
❌ tags   scene=work,study,fun,create,travel（5 个 scene，超上限）
          · attr=free,zh-ui,no-login,open-source,ads-free
          · platform=web,ios,android · price=free · quality=editor-pick
          （一共 14 个标签，实际界面只有英文，还随手给了 editor-pick）
```

问题：`scene` 打了 5 个（上限 3），等于没打；界面只有英文却标了 `zh-ui`，
标签与事实不符比不标更伤；14 个标签说明这条定位不清，会在十几个标签页里挤掉真正对口的条目；
`editor-pick` 是全站 15% 额度的东西，不能随手给。

```
✅ tags   type=tool · scene=work · platform=web · attr=free,no-login · price=freemium
          （共 5 个标签，scene 1 个）
          等它真的用了半年、确实是同类首选，再考虑加 quality/editor-pick。
```

## 九、投稿审核对照表（`/admin/submissions`）

| 情况 | 操作 | 拒绝原因选哪个 |
|---|---|---|
| 三条硬性门槛全过 | 「通过」→ 跳到 `/admin/entries/new` 补标签后保存 | — |
| 链接打不开 / 已经停止服务 | 「拒绝」 | 链接失效 |
| 需要装来路不明客户端、频繁换域名、纯导流站、停更超 2 年 | 「拒绝」 | 不符合收录标准 |
| 已经有同一条（或同一个东西换了域名） | 「拒绝」，已有条目重命名/改状态即可 | 重复 |
| 明显是推广、与收录范围无关、带一串跟踪参数 | 「拒绝」 | 垃圾信息 |

判断顺序永远是：**先看门槛，再看加分项，最后才看文案**。
门槛不过的，文案写得再好也不收；门槛过了的，文案可以收进来之后再慢慢改。
